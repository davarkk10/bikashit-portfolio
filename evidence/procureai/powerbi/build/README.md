# ProcureAI Model Results: Power BI build

`../ProcureAI_Model_Results/` is a Power BI Project (.pbip) generated by these scripts, with a `.pbit` template beside it and the CSVs it imports in `data/`. Open instructions are in its `README.txt`.

## Report pages

| Page | What it shows |
|---|---|
| Home | Headline results, what PR-AUC means, links to each page |
| Invoice risk | Model vs best hand-written rules, share of each condition caught, review queue of test invoices |
| Late delivery | Order-time and pre-arrival PR-AUC, late rate vs predicted risk by month, late rate by supplier load, driver importance, watch list |
| Contract assistant | 64/68 on the locked question set, accuracy by question type, every question with its answer and citation |
| About | How it was built, how to read the numbers, limits |

## Model

`dim_date`, `dim_supplier`, `dim_warehouse` filter `fact_po` (53,057 purchase orders used in modelling, with test-window scores) and `fact_invoice` (51,692 invoices, with test-window scores). `model_results`, `invoice_catch`, `driver_importance` and `contract_qa` hold results that can't be recomputed in DAX, such as PR-AUC. 45 measures sit in `_Measures`; precision, recall and late rates are computed live from the scored rows.

## Rebuild

```bash
# 1. data (from evidence/procureai)
python src/generate_procureai_data.py
python invoice_anomaly_v2/invoice_anomaly_v2.py data/raw data/ground_truth out_inv pbi_data
python ml_delay_rebuild/enrich_delivery_drivers.py data/raw data/v3
python ml_delay_rebuild/supplier_delay_v3.py data/raw data/v3 out_v3 pbi_data
python contract_assistant_v2/evaluate.py documents contract_assistant_v2/questions/heldout.jsonl heldout_first_run.json
python powerbi/build/build_pbi_data.py data/raw pbi_data out_inv/invoice_v2_results.json out_v3/delay_v3_results.json heldout_first_run.json
# 2. project
python powerbi/build/build_pbip.py pbi_data
python powerbi/build/check_pbip.py powerbi/ProcureAI_Model_Results
```

`check_pbip.py` confirms every JSON file parses, every DAX column and measure reference resolves, every field a visual uses exists, CSV headers match the model, and every page button points at a real page.
